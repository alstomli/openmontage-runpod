SRE review — supplied-asset prototype
Project date: 2026-11-04 (America/New_York)

Scope
Independent failure-injection and control-plane tests in tests/reliability/test_recovery.py.
These tests do not claim real Runpod deployment, live S3 compatibility, GPU generation,
or narration/creative quality. Actual rendering is covered by separate container smoke evidence.

Verified checks
- Durable replay through replacement Runner and storage object.
- Same idempotency key with changed input is rejected.
- Missing/corrupted cached artifacts are reconstructed rather than reported intact.
- Approval is required for the exact plan content hash; revised plans do not inherit approval.
- Source media mutation after approval is rejected by digest.
- Contradictory digests for the same source key are rejected.
- Media failure releases project lock; the same request can be retried.
- Concurrent access and crash-leftover locks fail closed.
- Traversal and cross-project input references are rejected.
- Unexpected exceptions do not leak exception text in the client response.
- Array/object enum values return invalid_input.
- S3 adapter mock checks atomic IfNoneMatch lock creation, conflict handling,
  missing-object errors, response-body closure, and URL regeneration.
- Installed botocore service model exposes PutObject.IfNoneMatch.
- Pinned Runpod SDK run_job extracts handler top-level error into SDK error channel;
  success output and metadata handling are checked separately.

Defects resolved before final build
- Initial image accepted contradictory sha256 values for one repeated source key.
  Current schema rejects this; regression test included. Final rebuilt image must pass.
- Media subprocess failures originally discarded diagnostic output. Developer added
  bounded operator-side diagnostic logging while preserving a safe API error response.

Operational limits
- Locks deliberately have no automatic expiry. After hard process termination, an
  operator must verify the old job is stopped before deleting its exact lock object.
- Endpoint authorization is trusted single-account usage; tenant isolation/auth policy
  beyond project-scoped storage references is not implemented.
- For renderer/upstream changes, bump wrapper version and use fresh idempotency keys.
  Current request receipts do not automatically invalidate across code deployments.
  Build-fingerprint cache namespaces are a future upgrade requirement.
- Live storage must prove conditional PutObject behavior against the chosen provider.
- Published artifact must be the exact image that passed final tests and offline render.
